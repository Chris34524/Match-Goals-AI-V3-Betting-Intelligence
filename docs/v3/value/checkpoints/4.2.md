# Checkpoint 4.2 — Minimum acceptable odds and selector

Issue #33 implemented after checkpoint 4.1 was validated (1026 tests passed).
Full V3 suite after implementation: 1087 passed; final evidence is generated by
`python -m v3.value.phase4_validation` in `docs/v3/phase-4-validation-report.json`.

## Policy and mathematics

Immutable policies identify id/version and all five supported markets. Per-market
parameters: safety_margin=0.05, min_ev=0.05, min_absolute_edge=0.02,
min_relative_edge=0.05. These conservative **synthetic defaults have no historical
validation**. No TEST/OOS, outcome labels, ROI, profit or win rate were used.
Config thresholds must be finite non-boolean numeric values in [0,1]. This V1
bound rejects absurd configurations; missing markets or identity are invalid.
Omitted per-market parameters use the documented defaults; exported policies
always contain every parameter. Policy changes require an explicit new version.

For p>0 and fair=1/p:

- minimum_odds_markup = fair * (1+safety_margin)
- minimum_odds_ev = (1+min_ev)/p
- minimum_acceptable_odds = max(markup, EV threshold)

Both methods are always active and recorded individually. Zero margins express
an inactive additional margin. p<=0 or overflow => BLOCKED/no computable minimum,
never infinity. Python float precision is retained throughout, with no rounding.
The price comparison is >=, including exact equality. The EV gate compares odds
against the equivalent minimum_odds_ev boundary; this prevents cancellation in
`p*odds-1` from rejecting mathematical equality. Reported EV remains the unchanged
4.1 formula. Edge gates compare the unrounded 4.1 metrics directly.

## Selector and contracts

PASS: all price/EV/absolute-edge/relative-edge gates pass.
NO_BET: valid eligible evidence fails at least one value gate.
BLOCKED: invalid evidence, incomplete market, temporal/source/price failure,
noncomputable minimum, or a candidate changed since its 4.1 evaluation.

Reasons are deterministic arrays in gate order: odds_below_minimum,
edge_below_threshold, relative_edge_below_threshold, ev_below_threshold.
Blocked reasons preserve 4.1's exclusion code; candidate_integrity_mismatch and
minimum_odds_not_computable are selector additions.

Serialized eligibility and metrics are never trusted: the selector replays the
original model target and observation envelopes in provenance. Synthetic mode
requires an explicit caller option again. Production defaults to fail-closed.
Outputs include identity, model/market probabilities, prices, minimum, edges, EV,
policy identity and components, observation/cutoff and full replay evidence.
No executable order, sizing, Kelly, bankroll or forecast-return fields exist.

## Sensitivity and CLI

Sensitivity consumes a fixed list of policies; it never creates, ranks or chooses
a policy. Each policy reports total and per-market candidate/PASS/NO_BET/BLOCKED
counts, reason counts, sorted edge/EV/minimum distributions (count, min, max,
values), and each candidate's gates. Distributions include available mathematical
metrics even for p=0 (selector BLOCKED); noncomputable/null values are excluded.
Candidate order follows input; policies and market/report keys are sorted.
Duplicate policy identities are rejected. No outcomes are input to this report.

From repository root, entirely offline:

```sh
python -m v3.value.cli evaluate \
  --input docs/v3/value/examples/input.json \
  --policy docs/v3/value/examples/default-policy.json \
  --synthetic-test-only --output /tmp/phase4-evaluation.json
python -m v3.value.cli sensitivity \
  --input docs/v3/value/examples/input.json \
  --policy docs/v3/value/examples/predefined-policies.json \
  --synthetic-test-only --output /tmp/phase4-sensitivity.json
```

Input is a JSON list (or `--input-jsonl`) of `{model, observations}` inputs or
4.1 output candidates. Each observation is `{record, cutoff, period, rules}`;
record is the unchanged Phase 3 canonical odds contract. Scope/clock metadata
must agree with the model target. Period and settlement rules are explicit,
for example full_time/90_minutes_including_stoppage_no_extra_time. Output is
JSON, or `--jsonl` for one candidate per line (sensitivity: one report per line).
Nonfinite JSON input is rejected. No connection to main.py or operational flow.

Coverage includes both minimum components and max combination; adjacent-float
price boundaries and equality; edge/relative/EV rejection; policy bounds and
market isolation; invalid/zero-probability/source/closing/postkickoff cases;
replay tampering; deterministic sensitivity; no optimization/sizing fields;
and JSON/JSONL CLI with sockets disabled.

Gaps: source authorization remains unavailable; defaults and probabilities have
no historical validation. These are decision-analysis outputs only. Phase 5
must preserve evidence eligibility and explicit policy versions.
