## Schedule and execution

scheduler.py accepts explicit validated Target objects: internal ID, external ID
when known, sport, competition, season, kickoff, home, away, markets and P0–P3
priority. Live plans require external IDs. There is no league crawl, polling loop,
or operational scraper integration. An external timer invokes a single tick.

Canonical slots are T-24h, T-6h and T-1h. A window of **60 seconds after the due
instant**, configurable between 0 and 300, permits ordinary scheduling jitter.
Before the window, status is planned. After it, status is missed; equal/after
kickoff is always missed. A response outside the slot window is rejected; its raw
collector evidence can remain, but it is not credited as that slot. No retrospective
queries, backdating or missed-slot recovery occur. UTC-aware arithmetic handles
offsets. Offline fixture clocks simulate prospective captures only.

Decision snapshots are disabled by default. Configuration can enable a decision
offset such as 900 or 300 seconds, greater than the capture window and below one
hour. They receive the lowest slot budget priority, so they never displace the
canonical schedule. Budget ordering is P0→P3, then T-1h→T-6h→T-24h→decision,
then stable internal match ID. Soft/run/provider/hard bounds can mark skipped_budget.
The virtual plan considers future slots together; actual quota is reserved only
on execution. A later tick rechecks the ledger before network. executed, missed,
skipped_budget and failed are terminal for a match/slot within the chosen root;
no implicit retry or old-clock replay. Replanning requires an explicitly separate
campaign/root with coordinated quota, rather than rewriting history.

Per-tick immutable manifests contain planned/executed/missed/skipped_budget/failed
states, reasons, requested and covered markets/books, rejected count/reasons,
credits estimated/actual, source run IDs and both snapshot identity and content
digests. Unknown live consumption is null and remains conservatively reserved.
Locks serialize scheduler ticks and the collector quota ledger independently.

## Store and derivatives

snapshots.py wraps the unchanged canonical 3.1 record with slot, scheduled offset,
window, provider_last_update (source_published_at alias), run/source provenance and
explicit opening/closing accreditation flags. Identity is match/provider/book/
market/selection/line/slot/observed_at. Only a fully semantically identical JSON
observation, including provenance, deduplicates. Same identity with different
content is rejected; a later timestamp creates a new immutable observation.
History is never removed or overwritten.

movement.py compares only the same internal and external match, kickoff, provider,
book, market, selection and line, with increasing valid pre-match timestamps.
T24→T6, T6→T1 and T24→T1 retain both provenance endpoints. Metrics are decimal
odds delta, reciprocal probabilities before/after and delta, relative price change
(after/before − 1), elapsed seconds and shortened/lengthened/unchanged direction.
Repeated observations are preserved; all comparable pairs are reported, rather
than silently selecting one. Changes of line remain separate series.

Open-to-current requires snapshot_type=opening with definition and evidence that
pass 3.1. First capture does not confer opening. Closing likewise requires an
explicit closing type and accredited temporal definition/evidence; being the last
pre-kickoff observation confers nothing. The current API adapter emits current
only. No current-provider opening or closing accreditation is asserted.

clv.py returns computable, blocked or not_applicable. Without a decision observation
it is not_applicable; without accredited comparable closing it is blocked. Synthetic
accredited closing tests verify `clv_price = odds_taken / odds_close - 1`. Equal or
reversed timestamps, different lines, books, providers or markets are blocked.
**Real/current-provider CLV remains blocked.**

Dispersion requires at least two books, an explicit complete unique expected
population, the same run, exact observed_at, slot and series. Missing books are
not filled. It reports N, mean, median, min, max, range, sample stdev and mean
reciprocal odds as descriptive consensus (no margin removal). Captures with
different times or runs are not silently pooled. snapshot_report.py serializes
history, comparable movements and eligible populations deterministically.

## Invocation and gaps

```sh
python -m v3.odds.snapshots_cli plan --config tests/v3/fixtures/odds/config.json --targets tests/v3/fixtures/odds/targets.json --now 2026-11-01T17:00:00Z
python -m v3.odds.snapshots_cli fixture-tick --config tests/v3/fixtures/odds/config.json --targets tests/v3/fixtures/odds/targets.json --fixture tests/v3/fixtures/odds/response.json --now 2026-11-01T17:00:00Z
python -m v3.odds.snapshots_cli report --config tests/v3/fixtures/odds/config.json --targets tests/v3/fixtures/odds/targets.json
```

Live command is live-tick with --live, credentials and source grant; it disallows
fixture/time overrides. `live_status = blocked_missing_credentials`. No real API
calls occurred. External deployment of a timer, project licensing, actual coverage
and accredited closing evidence remain dependencies. Simultaneous books across
independent event captures are intentionally ineligible for consensus. No
historical subscription, Champion changes, picks, Kelly or staking were added.
